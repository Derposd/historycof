# Что нужно уточнить у заказчика

Вопросы из брифа плюс те, что всплыли во время разработки. Пока ответов нет,
код работает на заглушках: mock iiko, SMS в лог, пуши в лог. Каждая заглушка
переключается одной переменной окружения, код менять не нужно.

## Блокирующие (без ответа нет бонусной программы и публикации в сторах)

### 1. Доступ к iiko API
- **organizationId** и **apiLogin** (iikoWeb → Настройки → API-логины); логину нужны
  права на программу лояльности.
- Какая программа лояльности настроена на кассе: **iikoCard** (штатная, через iikoCloud)
  или **внешняя** через iikoBiz / плагин. Приложение сделано под iikoCard; внешняя
  программа потребует другой адаптер (интерфейс `IikoLoyaltyClient` это позволяет).
- Включена ли программа и принимает ли касса карту по **сканеру штрих-/QR-кода**. Приложение
  показывает трек карты в QR и Code128, и кассир должен уметь его отсканировать.

Подробнее и чек-лист проверки: [iiko-integration.md](iiko-integration.md).

### 2. Правила бонусов
Процент начисления, минимальная сумма и максимальная доля оплаты бонусами, срок сгорания,
приветственные бонусы, уровни. Всё это считает iiko. В приложении нужны только тексты
для экрана «Бонусы» (сейчас там общая подсказка «покажите код бариста»).

### 3. Куда присылать обращения из «Жалобы»
Готовы три канала, работают одновременно:
- раздел «Обращения» в админке (есть всегда);
- **Telegram-бот**: нужен токен от @BotFather и chat_id чата или группы управляющего;
- **email**: адрес получателя и SMTP-доступ (например, Яндекс 360).

### 4. Кто ведёт меню
Сейчас меню ведётся вручную через админку. Если меню уже заведено в iiko с фото и составом,
можно сделать импорт из номенклатуры iiko (`/api/1/nomenclature`) — это отдельная задача.
Бейджи и «истории блюд» в iiko не хранятся, их всё равно придётся заполнять в админке.

### 5. Логотип и бренд-бук
Нужен **вектор** (SVG/AI/PDF): словесный знак HISTORY с пером и монограмма-филигрань.
Сейчас логотип нарисован по скриншотам (`mobile/lib/core/widgets/wordmark.dart`).
Из того же вектора сделаем иконку приложения и сплэш: сейчас стоят стандартные иконки Flutter.

### 6. Сторы
- Название в сторах (предложение: «History Coffee»), короткое и полное описание.
- Аккаунты разработчика: **Google Play Console** (для РФ: RuStore как дополнительный
  канал) и **Apple Developer Program**. Если аккаунты на заказчика, нужно приглашение.
- Скриншоты для стора сделаем, когда будет наполнено меню.

## Нужны для запуска

7. **Реквизиты для политики ПДн**: ИНН и ОГРНИП ИП Жабоевой А. Т., email для запросов
   по персональным данным. Текст политики — черновик в `backend/src/legal/privacy-policy.ts`,
   его должен проверить юрист.
8. **Уведомление Роскомнадзора** об обработке ПДн. Если оператор ещё не в реестре,
   его нужно подать до запуска. Отдельно — вопрос трансграничной передачи
   (Firebase Cloud Messaging — сервис Google, туда уходит только технический токен устройства).
9. **SMS-шлюз**: аккаунт у провайдера (в коде SMS.ru, легко заменить на SMSC / SMS Aero /
   МТС Exolve) и зарегистрированное буквенное имя отправителя «HISTORY».
10. **Firebase-проект** для push (создаём мы или заказчик) и APNs-ключ из Apple Developer.
11. **Хостинг в РФ** (152-ФЗ, локализация): предлагаем Yandex Cloud или Selectel —
    managed PostgreSQL, Object Storage для картинок, небольшая VM или Serverless Containers.
    Нужны домен или поддомен для API и админки (например, `api.historycoffee.ru`, `admin.historycoffee.ru`).

## Сверить с исходниками

12. **Меню с сайта.** Из среды разработки historycoffee.ru был недоступен (сетевой запрет),
    поэтому позиции меню **не перенесены**. В сид попала только структура разделов
    (Кухня: Завтраки, Салаты, Боулы, Основное, Тосты·Сэндвичи; Бар) и капучино 270/290 ₽ из брифа.
    Состав категорий **Бара** (сейчас одна категория «Кофе») нужно сверить с сайтом.
13. **Instagram @history.coffee.ru** напрямую не проверен. Ссылка стоит в контактах,
    перед релизом проверить имя аккаунта.
14. **Координаты точки** на карте. Без них маршрут строится по адресу «г. Нальчик, ул. Толстого, 43».
    Координаты можно ввести в админке («Контакты и часы»).
15. **Отзывы с Яндекс.Карт.** На сайте есть блок отзывов. В приложение он не входил по ТЗ.
    Если нужен, лучше давать ссылку на карточку в Яндекс.Картах, а не копировать тексты.
