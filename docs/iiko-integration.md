# Интеграция с iiko (бонусная программа)

## Принцип

Приложение **не начисляет и не списывает** бонусы. Это делает касса iiko, когда
бариста сканирует карту гостя. Приложение:

1. находит гостя в iikoCard по номеру телефона, а если его нет — регистрирует;
2. гарантирует, что у гостя есть карта; если карты нет, **выпускает виртуальную**
   (трек `7707XXXXXXXX`, префикс задаётся `IIKO_VIRTUAL_CARD_PREFIX`) и привязывает её к гостю в iiko;
3. показывает трек карты в QR-коде и Code128 (крупный режим — для сканера);
4. читает баланс кошельков и историю операций.

```
Гость ── телефон + SMS ──▶ Backend ── iikoCloud API ──▶ iikoCard
  │                          │  ▲
  │  QR с треком карты       │  └── баланс, история (read-only)
  ▼                          │
Касса iiko ── скан QR ──▶ iikoCard: начисление / списание
```

Если у гостя уже есть пластиковая карта в iiko, приложение использует её трек
и не выпускает новую.

## Используемые методы iikoCloud API

База: `https://api-ru.iiko.services` (`IIKO_BASE_URL`).

| Метод | Зачем |
|---|---|
| `POST /api/1/access_token` | токен по apiLogin (кэшируется на 45 минут, обновляется при 401) |
| `POST /api/1/loyalty/iiko/customer/info` (`type: phone` / `id`) | найти гостя, его карты и кошельки |
| `POST /api/1/loyalty/iiko/customer/create_or_update` | зарегистрировать гостя (согласие на ПДн получено в приложении, `consentStatus: 1`) |
| `POST /api/1/loyalty/iiko/customer/card/add` | привязать виртуальную карту |
| `POST /api/1/loyalty/iiko/customer/transactions/by_date` | история начислений и списаний |

Код: `backend/src/loyalty/iiko/iiko-cloud.client.ts`. Для разработки есть
`MockIikoClient` (`IIKO_MODE=mock`): при первом входе гость получает 150 демо-бонусов.

## Что включить

```env
IIKO_MODE=cloud
IIKO_API_LOGIN=<apiLogin из iikoWeb>
IIKO_ORGANIZATION_ID=<uuid организации>
```

`organizationId` можно получить так: `POST /api/1/organizations` с токеном этого apiLogin.

## Чек-лист проверки на реальной организации

Схемы ответов iiko различаются между версиями и настройками программы, поэтому маппинг
сделан защитно. Его **нужно сверить на живых данных** до запуска:

- [ ] `customer/info` для существующего гостя возвращает `cards[].track` и `walletBalances[].balance`.
- [ ] Для несуществующего телефона iiko отвечает 400 с текстом «not found / no user». Проверить
      точный текст и при необходимости поправить `IikoHttpError.isNotFound`.
- [ ] `card/add` принимает трек `7707XXXXXXXX`. Если в iikoCard настроен шаблон номеров карт,
      подобрать префикс или формат.
- [ ] Касса находит гостя по скану QR (сканер работает как клавиатура и вводит трек).
      Если касса не принимает QR, проверить Code128 из крупного режима.
- [ ] `transactions/by_date` содержит сумму (`sum`) и дату (`whenCreated`). Проверить знак
      списаний: `mapTransaction` инвертирует положительные суммы у типов «Pay / Withdraw / списание».
- [ ] Какие кошельки показывать. Сейчас баланс — сумма всех `walletBalances`. Если в программе
      есть депозитный кошелёк, его стоит исключить по `type`.
- [ ] Сквозной тест: покупка на кассе со сканом карты → через ~30 с (кэш) баланс в приложении
      вырос, в истории появилась операция.

## Отказоустойчивость

- Если iiko недоступен, API отвечает `503 loyalty_unavailable`, приложение показывает спокойную
  ошибку с кнопкой «Повторить». Остальные разделы работают.
- Баланс кэшируется на 30 секунд на гостя. Pull-to-refresh на экране бонусов
  (`GET /loyalty?refresh=true`) обходит кэш.
- Удаление аккаунта в приложении **не удаляет** гостя в iiko: это бонусный счёт кофейни.
  Удаление в iiko выполняется по отдельному запросу, как описано в политике ПДн.
