# Соответствие законодательству РФ

Проверено 30.09.2026 по требованиям, действующим и вступающим в силу на эту дату. Документ —
рабочий чек-лист разработчика, а не юридическое заключение: **перед публикацией в магазинах
приложений тексты документов и этот список должен посмотреть юрист кофейни.**

Условные обозначения: ✅ — сделано в приложении, 🏪 — должна сделать кофейня (оператор),
⚠️ — решение за кофейней.

## 1. Персональные данные — 152-ФЗ «О персональных данных»

| Требование | Статус | Как устроено |
|---|---|---|
| Согласие на обработку — **отдельный документ**, не часть политики или других текстов (ст. 9, ред. 156-ФЗ, с 01.09.2025) | ✅ | Отдельный текст «Согласие на обработку персональных данных» (`/legal/consent`), отдельная галочка при регистрации, по умолчанию снята |
| Содержание согласия: оператор, перечень данных, цели, действия, обработчики, срок, порядок отзыва (ст. 9 ч. 4) | ✅ | Текст в `backend/src/legal/documents.ts`, реквизиты и обработчики — из админки |
| Доказательство получения согласия — на операторе (ст. 9 ч. 3) | ✅ | Журнал `consents`: вид, версия текста, время, IP, устройство; отзыв — `revoked_at` |
| Повторное согласие при изменении текстов | ✅ | Версия `LEGAL_VERSION`; при её смене приложение просит согласие заново, без согласия — выход из аккаунта |
| Политика обработки опубликована и доступна (ст. 18.1) | ✅ | В приложении (вход, профиль → «Документы») и веб-страницей `/api/v1/legal/privacy/page` — ссылка для RuStore / Google Play |
| Наименование и адрес оператора в согласии (ст. 9 ч. 4 п. 1) | ✅ / 🏪 | Админка → «Контакты и часы» → «Продавец и документы»: наименование (обязательно) и адрес (пусто — адрес кофейни); почта для запросов — по желанию. ИНН/ОГРН закон в согласии не требует — не собираем и не показываем |
| Перечень обработчиков по поручению (iiko, SMS, хостинг, уведомления) с наименованиями (ст. 6 ч. 3) | 🏪 | Сейчас в документах — типовой перечень без названий (`PROCESSORS` в `backend/src/legal/documents.ts`). Кофейня сообщает названия компаний — разработчик вписывает их и повышает `LEGAL_VERSION`; с каждой — договор поручения |
| Локализация: базы с данными граждан РФ — на территории РФ (ст. 18 ч. 5) | 🏪 | Боевой сервер, база и хранилище фото — у российского провайдера (Selectel, Yandex Cloud, Timeweb и т. п.). Тестовый стенд — только для проверки, с тестовыми номерами |
| Трансграничная передача (ст. 12) | ⚠️ | Push-уведомления через Firebase Cloud Messaging (Google, США): передаётся только токен устройства и текст уведомления, без телефона и имени. Варианты: подать в Роскомнадзор уведомление о трансграничной передаче **или** перейти на RuStore Push (российский сервис) — это отдельная доработка |
| Уведомление Роскомнадзора об обработке ПДн (ст. 22) — до начала обработки | 🏪 | Подать на pd.rkn.gov.ru; указать сведения о локализации и обработчиках |
| Сроки хранения и уничтожение (ст. 5 ч. 7, ст. 21) | ✅ | Ежедневная очистка (`backend/src/retention`): коды — сутки, токены — 30 дней после истечения, обращения — 3 года, неактивные 3 года аккаунты — удаляются |
| Отзыв согласия / удаление аккаунта | ✅ | Профиль → «Удалить аккаунт»: данные профиля стираются сразу, из обращений убираются телефон и фото (файлы удаляются), согласия отзываются |
| Данные в iiko при удалении аккаунта | 🏪 | Удаление карты гостя в iiko — процедура кофейни по запросу гостя (указано в политике) |
| Права субъекта: ответ на запрос за 10 рабочих дней (ст. 14, 20) | 🏪 | Почта для запросов — в реквизитах; назначить ответственного за обработку ПДн (ст. 18.1, 22.1) |
| Защита данных (ст. 19) | ✅ / 🏪 | HTTPS обязателен на боевом сервере (тестовый стенд — без него), хэши кодов и паролей, роли в админке. Кофейне — локальные акты: положение о ПДн, приказ об ответственном, перечень допущенных сотрудников |

## 7. Прочее

- **Возрастная маркировка (436-ФЗ):** в приложении указано «0+»; в RuStore / Google Play выбрать ту же категорию.
- **Магазины приложений:** для RuStore и Google Play нужна ссылка на политику — `https://<домен>/api/v1/legal/privacy/page`; в анкете Google Play «Безопасность данных» перечислить: телефон, имя, дата рождения (необязательно), фото (необязательно), идентификатор устройства.
- **Шрифты и библиотеки:** только свободные лицензии (SIL OFL, BSD, MIT, Apache), тексты лицензий — в приложении (Профиль → «Лицензии»).
- **Логотип** — собственность кофейни, используется с её согласия (`docs/brand/README.md`).

## Что кофейне сделать до запуска (короткий список)

1. Проверить в админке «Продавец и документы» наименование и адрес (почта — по желанию); сообщить разработчику названия компаний-обработчиков и условия бонусной программы.
2. Отдать тексты документов (ссылки там же, в админке) на проверку юристу.
3. Подать в Роскомнадзор уведомление об обработке ПДн; решить вопрос с push (уведомление о трансграничной передаче или RuStore Push).
4. Разместить боевой сервер, базу и фото у российского провайдера, подключить домен с HTTPS.
5. Подключить российского SMS-провайдера.
6. Заключить договоры поручения обработки с iiko-интегратором, SMS-провайдером, хостингом.
7. Проверить товарный знак «History Coffee»; подготовить локальные акты по ПДн, назначить ответственного.
8. Заполнить пищевую ценность и аллергены блюд по техкартам.
